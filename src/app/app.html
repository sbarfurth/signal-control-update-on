Reproduction: FormValueControl ignores updateOn

When a custom component implements Signal Forms FormValueControl<T> (without legacy ControlValueAccessor), Angular's NgControl.ngControlCreate listens to valueChange and immediately calls control.setValue(), bypassing control.updateOn ('blur' / 'submit').

1. Reactive Forms: updateOn: 'blur'

Type into both inputs without blurring. The native input keeps control.value empty until blur, whereas FormValueControl updates control.value on every keystroke.

FormValueControl (Buggy)

control.value: "{{ signalBlurControl.value }}"
dirty: {{ signalBlurControl.dirty }}
touched: {{ signalBlurControl.touched }}

Native <input> (Expected)

control.value: "{{ nativeBlurControl.value }}"
dirty: {{ nativeBlurControl.dirty }}
touched: {{ nativeBlurControl.touched }}

2. Reactive Forms: updateOn: 'submit'

Type into both inputs and blur without clicking Submit. The native input defers updating form.value until submit, whereas FormValueControl updates immediately on input.

FormValueControl (Buggy)

control.value: "{{ submitForm.controls.signalSubmit.value }}"
dirty: {{ submitForm.controls.signalSubmit.dirty }}
touched: {{ submitForm.controls.signalSubmit.touched }}

Native <input> (Expected)

control.value: "{{ submitForm.controls.nativeSubmit.value }}"
dirty: {{ submitForm.controls.nativeSubmit.dirty }}
touched: {{ submitForm.controls.nativeSubmit.touched }}

3. Template-Driven Forms: [ngModelOptions]="{ updateOn: 'blur' }"

FormValueControl (Buggy)

ngModel signal: "{{ ngModelSignalValue() }}"

Native <input> (Expected)

ngModel signal: "{{ ngModelNativeValue() }}"
